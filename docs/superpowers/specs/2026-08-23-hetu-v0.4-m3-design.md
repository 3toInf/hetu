# Hetu v0.4 M3 — Web HITL/操作闭环

> 日期：2026-08-23　状态：待评审（Draft for review）
> 上游：v0.4 M2 [./2026-08-23-hetu-v0.4-m2-design.md](./2026-08-23-hetu-v0.4-m2-design.md)（只读 Web 前端，已合并）；完整需求 [../../requirements.md](../../requirements.md)（§17 "Hetu 不应该只是一个 Session Browser"、§14 分页、§22/23 Remote）。
> 本文件是 v0.4 第三个里程碑（M3）的**实现规格**：把 M2 的只读 Web 变成操作闭环——在浏览器里审批、发送、恢复会话，并实时看到驱动会话的状态变化。

---

## 1. 目标与非目标

**目标（M3）**
- **写操作 HTTP 端点**：approve/deny、send、resume、create、mark_read —— 全部复用现有 dispatch op，业务零重复。
- **CSRF 防御**：所有 `POST /api/*` 强制 `Content-Type: application/json`，违规 415。
- **SSE 实时事件流**：`GET /api/sessions/{id}/events`（Server-Sent Events），浏览器实时看到 status/approval/text 事件。
- **get_session `?limit=` 透传**：修 M2 transcript 硬顶 20 条的问题（默认提到 200）。
- **前端 SessionView 交互化**：pending 审批卡（Approve/Deny 按钮）、send 输入框、Resume 按钮、SSE 实时追加、打开时自动 mark_read。
- **前端 SessionsView**：load-more 分页（§14）+ 10s 轮询刷新徽章（live 感）。
- **e2e smoke（gated）**：真实 claude 驱动会话，全程走 HTTP：create/send → WaitingForApproval → HTTP approve → 工具真跑完。

**非目标（推后）**
- 多引擎（Codex/OpenCode）→ v0.5（v0.3 提取器注册制已铺路）。
- Remote Host / 认证 / 多用户 → 单机 localhost 可信模型不变。
- 搜索深分页、结果高亮 → 后续。
- driven 会话实时消息落库进 FTS → M2 后评估项，M3 的实时渲染走 SSE 内存流，不写库。
- WebSocket / 双向推送 → SSE（单向）够用；浏览器原生 `EventSource` 自动重连。

## 2. 关键决策

| 项 | 决策 | 理由 |
|---|---|---|
| 写操作接入 | 与 M2 相同：HTTP handler 构造 `api.Request` 走 `Server.dispatch`（`ws.call`） | approve/send/resume/create/mark_read 五个 op 在 dispatch 里已是完整逻辑（含 "not found"→404、多 pending 校验），一行不重写 |
| CSRF 防御 | **POST /api/* 强制 `Content-Type` media type 为 `application/json`**（`mime.ParseMediaType` 解析，允许 `; charset=utf-8` 参数），违规 → 415 | M2 的 Host 校验只防 DNS rebinding，防不了恶意页面直发 `http://127.0.0.1:19191` 的 HTML 表单 POST（副作用照发生）。跨站表单只能发 urlencoded/multipart/text/plain 三种类型；fetch 发自定义类型会触发 CORS preflight，而本服务不发 CORS 头 → 被浏览器拦。**免 token、对真前端零摩擦**（前端本来就发 JSON） |
| deny 的形态 | 不设独立 deny 端点；`POST /api/sessions/{id}/approve` body `{"allow": false}` 即 deny | 与 `api.ApproveReq{Allow bool}` 一一对应，少一个端点 |
| 实时流 | **SSE，不走 httpWriter 适配器**：handler 直接 `mgr.Subscribe(hetuID)`，逐事件写 `data: <json>\n\n` + Flush；`r.Context().Done()` → `cancel()` | httpWriter 假设每 op 恰好一次写（单响应模型），流式 op 会写多次；`subscribe` op 在 dispatch 里也是直接 range channel。SSE 是服务器→浏览器单向流，`EventSource` 原生支持自动重连，比 WebSocket 简单得多 |
| 会话结束信号 | pump 关闭 subscriber channel 时，SSE 写 `event: end` 后返回；前端收到 end 主动关 `EventSource` | 浏览器对静默断开会无限重连；非 driven 的会话重连只会得到 400。前端收到 end = 明确终点 |
| 心跳 | 每 15s 写 SSE comment `: ping\n\n` + Flush | 防中间层/浏览器空闲超时断连；localhost 上也无害 |
| transcript limit | `api.GetSessionReq` 加 `Limit int`；dispatch 里 `<=0 → 200`（原硬编码 20）；web 层从 `?limit=` 解析 | 20 太小（真实会话动辄上百条）；CLI `hetu session --limit` 走同一 op，默认也受益 |
| 会话列表分页 | `api.ListSessionsReq` 加 `Limit int` 透传给 `ListFilter.Limit`（store 已支持）；前端 load-more = `limit += 50` 重拉全列表 | 排序稳定（status 优先级 + updated_at DESC），扩 limit 重拉结果前缀一致；单机数据量下重复传输可忽略，省掉 offset/游标复杂度（YAGNI）。返回条数 < limit 即到底，隐藏按钮 |
| SessionsView "实时" | 10s `setInterval` 重拉（页面可见时），无 in-flight 重入 | 每行开 SSE 过重；列表徽章 10s 粒度足够 "live 感"，实现 ~10 行 |
| mark_read | SessionView 挂载且 `session.unread` 时 `POST /api/sessions/{id}/mark_read` | 闭环：看过了就该消未读点（与 CLI 行为一致） |

## 3. HTTP API 增量（web.go）

| 方法 + 路径 | body（JSON） | 内部 op | 响应 |
|---|---|---|---|
| `POST /api/sessions/{id}/approve` | `{"allow": bool, "tool_use_id"?: string, "reason"?: string}` | `approve` | `{"ok": true}` |
| `POST /api/sessions/{id}/send` | `{"prompt": string}` | `send` | `{"ok": true}` |
| `POST /api/sessions/{id}/resume` | `{}` | `resume` | `{"id": "...", "driven": true}` |
| `POST /api/sessions/{id}/mark_read` | `{}` | `mark_read` | `{"ok": true}` |
| `POST /api/sessions` | `{"project_path": string}` | `create` | `{"id": "..."}` |
| `GET /api/sessions/{id}`（增强） | query `?limit=N` | `get_session` | 同 M2，messages 受 limit |
| `GET /api/sessions`（增强） | query 增 `?limit=N` | `list_sessions` | 同 M2 |
| `GET /api/sessions/{id}/events` | — | 直接 `mgr.Subscribe`（SSE） | `text/event-stream` |

**已有端点变化**：`POST /api/discover` 也开始受 Content-Type 守卫约束（一致性；前端同步加 header）。

**CSRF 守卫实现**：`Handler()` 的 mux 前加一层（与 hostAllowed 同一包装）：`r.Method == "POST"` 且 path 以 `/api` 开头时，`mime.ParseMediaType(r.Header.Get("Content-Type"))` 失败或 media type ≠ `application/json` → `415` + `{"error":"content-type must be application/json"}`。GET 无 body，不受约束。

**错误映射**：沿用 M2 httpWriter（"not found"→404，其余→400，JSON body）。SSE 端点在切换到 event-stream **之前**校验：会话不存在 → 404；`errNotDriven`（会话不在 live 表）→ 400 `{"error":"session not driven"}`。

## 4. SSE 协议（`GET /api/sessions/{id}/events`）

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache

retry: 3000

: ping                      ← 每 15s 心跳 comment

data: {"type":"status","status":"WaitingForApproval","seq":0}

data: {"type":"approval","tool_use_id":"toolu_01...","tool_name":"Bash","tool_json":"{...}","approval_state":"pending","seq":0}

data: {"type":"approval","tool_use_id":"toolu_01...","approval_state":"allowed","seq":0}

data: {"type":"text","text":"...assistant 增量...","seq":42}

event: end
data: {}
```

- `data:` 载荷 = `agent.Event` 的 JSON（`internal/agent/event.go`，已有 json tags，逐字段透传不改）。
- `approval_state` 值域：`pending` / `allowed` / `denied` / `timeout`（sessionmanager broadcast 现状）。
- 无 `event:` 字段的事件走 `EventSource` 的 `message` 通道；`end` 是命名事件，只有显式监听才收到——前端监听它来关闭连接。
- handler 生命周期：`ResolveSession`（404）→ `mgr.Subscribe`（400 not driven）→ 写头 + `retry` → `for { select sub / ctx.Done / ticker }`；任一退出路径 `defer cancel()` 退订（复用 v0.2 生命周期：pump 结束时 close 所有 subscriber channel → range/select 收到 closed → 写 `event: end` 返回）。
- 断连即退订：浏览器关页面/断网 → `r.Context().Done()` → `cancel()`，不泄漏 subscriber。

## 5. 前端（web/src）

### api.ts 增量
```ts
async function post<T>(url: string, body: unknown): Promise<T>   // Content-Type: application/json，非 2xx 抛错
approve(id, allow: boolean, toolUseID?: string)
send(id, prompt: string)
resume(id)
markRead(id)
createSession(projectPath: string)
session(id, limit?: number)        // ?limit= 透传
```
已有 `discover()` 改走 `post()`。

### types.ts 增量
```ts
interface PendingApproval { tool_use_id: string; tool_name: string; tool_input: string }
interface AgentEvent { type: string; text?: string; tool_name?: string; tool_json?: string;
  tool_use_id?: string; approval_state?: string; status?: string; err?: string; seq: number }
```

### SessionView（交互化）
- **pending 审批卡**：每张卡显示 tool_name + tool_input（`<pre>` 折叠）+ **Approve / Deny** 两按钮（携带各自 `tool_use_id`，天然支持多 pending 并存，不做下拉选择）。
- **send 输入框**：textarea + Send 按钮；`session.driven` 时可用，否则显示 **Resume** 按钮（有 external_id 时）；发送后本地追加 `{role:'user'}` 消息 + 清空输入。
- **SSE**：`session.driven` 时 `new EventSource('/api/sessions/{id}/events')`：
  - `status` → 更新状态徽章；
  - `text` → 追加 `{role:'assistant'}` 消息（本地 seq 递减避撞）；
  - `approval` pending → 加入 pending 列表；allowed/denied/timeout → 移除；
  - `end` → `es.close()` + 重新 `load()`（拉最终落库状态）；
  - 组件卸载/换会话 → `es.close()`。
- **mark_read**：挂载时 `session.unread` → 调 markRead + 本地清 unread。
- transcript 反转逻辑（M2 的 newest-first → oldest-first）不变；SSE 追加直接 push 到已反转数组的尾部。

### SessionsView（分页 + 实时）
- 初始 `?limit=50`；**Load more** 按钮：`limit += 50` 重拉；返回条数 < 当前 limit → 隐藏按钮（到底）。
- 10s 轮询 `load()`（`document.visibilityState === 'visible'` 时才拉；in-flight 守卫防重入）；`needs_attention` 行高亮（等待审批/输入/错误的醒目样式）。

## 6. 安全模型汇总

| 威胁 | 防御 |
|---|---|
| DNS rebinding（恶意域解析到 127.0.0.1 同源读） | M2 `hostAllowed`：非 loopback Host → 403（已有） |
| 跨站表单直发 POST（side-effect 强制发生） | **M3 Content-Type 守卫**：表单发不出 `application/json` → 415 |
| 跨站 fetch 发 JSON | 触发 CORS preflight；服务无 CORS 头 → 浏览器拦截 |
| 局域网他人访问 | 默认绑定 `127.0.0.1`（M2 已有） |

已知残余风险（记录，不处理）：本机其他进程可直接 POST——单机可信模型内，与 unix socket 同级暴露面。

## 7. 测试策略

- **web.go POST 端点**（`web_test.go`）：httptest 全端点——approve（走 fake agent 产生 pending？不：直接用 `NewSessionManager(st, resolver, nil)` + store-only 断言 400 "no pending approval" 路径 + 404 路径）；send/resume/mark_read/create 走 err 路径 + mark_read 成功路径（非 driven 也可 mark_read，纯 store 操作）。
- **CSRF 守卫**：POST `/api/discover` 用 `application/x-www-form-urlencoded` → 415；`application/json` → 200；GET 不受影响。
- **SSE**（`web_test.go`）：驱动一个 fake live session（复用 sessionmanager_test 的 fake agent 模式），GET events → 收到 `retry:`、status 事件 JSON、断连后 subscriber 被清理（cancel 幂等）；非 driven → 400。
- **limit 透传**：seed >20 条消息，`?limit=` 生效；无 limit → 200 条默认（seed 210 条断言截断）。
- **前端**：`npm run build`（vue-tsc）通过即门槛；行为人工核对。
- **e2e smoke（gated，真实 claude）**：`make build` → 起 hetud（web 开）→ 全程 HTTP：`POST /api/sessions`（create）→ `POST .../send`（"create /tmp/hetu-m3-smoke.txt with the word ok"）→ 轮询 `GET /api/sessions/{id}` 至 `WaitingForApproval` + pending 非空 → `POST .../approve {"allow":true}` → 轮询至 Completed → 断言文件存在 → `curl -N .../events`（期间有事件流）。结果记入 spec 附录。

## 8. 限制与未来

- 实时 text 事件只进内存 UI，不落 FTS（落库仍靠 discovery 扫 JSONL；driven 实时落库是 M3 后评估项）。
- SSE 无鉴权/无多路复用（一会话一连接）；Remote 场景需要认证层，届时一并重设计。
- Load-more 是"扩 limit 重拉"，万级会话时换真分页（offset/游标）。
- 浏览器多标签同时 approve 同一 tool_use_id：后到者得到 "no matching pending approval" 400——前端把它显示为友好提示即可，不做乐观锁。
