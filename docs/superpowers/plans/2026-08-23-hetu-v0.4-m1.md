# Hetu v0.4 M1 — Transcript Content + FTS5 Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store Claude session transcripts (message text) in SQLite with an FTS5 index, and expose them via `hetu session <id>` (show conversation) and `hetu search <query>` (full-text search).

**Architecture:** A `session_messages` table (structured, sortable, for display) plus a `session_messages_fts` FTS5 virtual table (for search), both written together on discovery. Discovery learns to extract per-message text from the JSONL it already parses, and — critically — to use a *stable* hetu_id (currently it mints a fresh uuid every discover, which would orphan message foreign keys). `search` switches from title-LIKE to FTS5 (with title fallback).

**Tech Stack:** Go 1.25, `modernc.org/sqlite` (FTS5 verified available), cobra CLI. **No new dependencies.**

**Spec:** `docs/superpowers/specs/2026-08-23-hetu-v0.4-m1-design.md`

## Global Constraints

- Go 1.25; `go test ./...` + `go vet ./...` green after every task; `-race` clean on daemon/client/cli.
- **No new dependencies** (stdlib only); cross-compile stays one-line (`make dist`).
- FTS5 is available in `modernc.org/sqlite` (verified); use it via plain SQL — no special build tags.
- **Message sync semantics are REPLACE, not insert-or-ignore** (this refines spec §2/§5): discovery re-scans a whole transcript file when it changed, and a rewritten JSONL invalidates old seq numbers, so `SyncMessages` deletes the session's existing messages (both tables) then re-inserts the full list. The `UNIQUE(session_hetu, seq)` constraint remains as a correctness backstop, not the idempotency mechanism.
- **Only `type:"text"` blocks are indexed** — `tool_use`/`tool_result` are skipped. Multi text blocks in one message are joined with `\n`.
- **Search query is a phrase**: wrap the user input in double quotes (after stripping any `"`), so `foo OR bar` is treated literally, not as an FTS5 operator.
- **Stable hetu_id in discovery** is a hard requirement (see Task 5) — messages must attach to the session id that `UpsertSession` already keeps, not a fresh uuid.
- Follow existing code style; conventional commits; TDD per task.

```go
package store

import (
	"context"
	"database/sql"
	"time"
)

type Message struct {
	Seq     int
	Role    string
	Content string
	TS      int64
}

// SyncMessages replaces all stored messages for a session (REPLACE semantics:
// a rewritten transcript invalidates old seq numbers, so delete-then-insert).
func (s *Store) SyncMessages(ctx context.Context, hetuID string, msgs []Message) error {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()
	if _, err := tx.ExecContext(ctx, `DELETE FROM session_messages WHERE session_hetu=?`, hetuID); err != nil {
		return err
	}
	if _, err := tx.ExecContext(ctx, `DELETE FROM session_messages_fts WHERE session_hetu=?`, hetuID); err != nil {
		return err
	}
	for _, m := range msgs {
		var ts any
		if m.TS != 0 {
			ts = m.TS
		}
		if _, err := tx.ExecContext(ctx, `INSERT INTO session_messages(session_hetu, seq, role, content, ts) VALUES(?,?,?,?,?)`,
			hetuID, m.Seq, m.Role, m.Content, ts); err != nil {
			return err
		}
		if _, err := tx.ExecContext(ctx, `INSERT INTO session_messages_fts(session_hetu, role, content) VALUES(?,?,?)`,
			hetuID, m.Role, m.Content); err != nil {
			return err
		}
	}
	return tx.Commit()
}

func (s *Store) RecentMessages(ctx context.Context, hetuID string, limit int) ([]Message, error) {
	q := `SELECT seq, role, content, COALESCE(ts,0) FROM session_messages WHERE session_hetu=? ORDER BY seq DESC`
	var args []any
	args = append(args, hetuID)
	if limit > 0 {
		q += ` LIMIT ?`
		args = append(args, limit)
	}
	rows, err := s.db.QueryContext(ctx, q, args...)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var out []Message
	for rows.Next() {
		var m Message
		if err := rows.Scan(&m.Seq, &m.Role, &m.Content, &m.TS); err != nil {
			return nil, err
		}
		out = append(out, m)
	}
	return out, rows.Err()
}

func (s *Store) SetContentSynced(ctx context.Context, hetuID string, unix int64) error {
	_, err := s.db.ExecContext(ctx, `UPDATE sessions SET content_synced_at=? WHERE hetu_id=?`, unix, hetuID)
	return err
}

func (s *Store) ContentSyncedAt(ctx context.Context, hetuID string) (int64, bool, error) {
	var v sql.NullInt64
	err := s.db.QueryRowContext(ctx, `SELECT content_synced_at FROM sessions WHERE hetu_id=?`, hetuID).Scan(&v)
	if err == sql.ErrNoRows {
		return 0, false, nil
	}
	if err != nil {
		return 0, false, err
	}
	return v.Int64, v.Valid, nil
}
```

```go
type SearchHit struct {
	HetuID  string
	Hits    int
	Snippet string
}

// SearchMessages runs a phrase query over the FTS index, aggregated per
// session with the number of matching messages and one snippet.
func (s *Store) SearchMessages(ctx context.Context, query string, limit int) ([]SearchHit, error) {
	if limit <= 0 {
		limit = 20
	}
	// phrase: strip quotes then wrap, so user input is literal
	phrase := `"` + strings.ReplaceAll(query, `"`, ` `) + `"`
	rows, err := s.db.QueryContext(ctx,
		`SELECT session_hetu, snippet(session_messages_fts, 2, '[', ']', '…', 12)
		 FROM session_messages_fts WHERE session_messages_fts MATCH ? LIMIT 500`, phrase)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	type agg struct {
		hetu string
		hits int
		snip string
	}
	order := []string{}
	m := map[string]*agg{}
	for rows.Next() {
		var hetu, snip string
		if err := rows.Scan(&hetu, &snip); err != nil {
			return nil, err
		}
		a, ok := m[hetu]
		if !ok {
			a = &agg{hetu: hetu, snip: snip}
			m[hetu] = a
			order = append(order, hetu)
		}
		a.hits++
	}
	if err := rows.Err(); err != nil {
		return nil, err
	}
	out := make([]SearchHit, 0, len(order))
	for _, h := range order {
		out = append(out, SearchHit{HetuID: h, Hits: m[h].hits, Snippet: m[h].snip})
	}
	sort.Slice(out, func(i, j int) bool { return out[i].Hits > out[j].Hits })
	if len(out) > limit {
		out = out[:limit]
	}
	return out, nil
}
```

```go
func (s *DiscoveryScheduler) Run(ctx context.Context) error {
	for name, src := range s.sources {
		ch, err := src.Discover(ctx, agent.DiscoverOpts{})
		if err != nil {
			continue
		}
		for d := range ch {
			proj, _ := s.resolve.ResolveByCWD(ctx, d.CWD)

			// Stable id: reuse the existing row's hetu_id; mint only for brand-new sessions.
			hetuID := uuid.NewString()
			if existing, ok, _ := s.store.GetSessionByExternal(ctx, name, d.ExternalID); ok {
				hetuID = existing.HetuID
			}

			_, _ = s.store.UpsertSession(ctx, store.Session{
				HetuID: hetuID, Agent: name, ExternalID: d.ExternalID,
				ProjectID: proj.ID, Host: "local", CWD: d.CWD, Title: d.Title,
				Status: d.Status, CreatedAt: d.CreatedAt, UpdatedAt: d.UpdatedAt,
			})

			// Sync messages only when the transcript file is newer than the last sync.
			syncedAt, synced, _ := s.store.ContentSyncedAt(ctx, hetuID)
			if !d.TranscriptMtime.IsZero() && (!synced || d.TranscriptMtime.After(time.Unix(syncedAt, 0))) {
				if len(d.Messages) > 0 {
					msgs := make([]store.Message, 0, len(d.Messages))
					for _, dm := range d.Messages {
						msgs = append(msgs, store.Message{Seq: dm.Seq, Role: dm.Role, Content: dm.Content, TS: dm.TS})
					}
					if err := s.store.SyncMessages(ctx, hetuID, msgs); err == nil {
						_ = s.store.SetContentSynced(ctx, hetuID, d.TranscriptMtime.Unix())
					}
				}
			}
		}
	}
	return nil
}
```

## Self-Review (author's notes)

**Spec coverage:** §3 schema → T1; §4 extraction → T4; §5 sync/incrementality → T2 (SyncMessages) + T5 (daemon); §6.1 session transcript → T6 (API) + T8 (CLI); §6.2 search → T3 (store) + T7 (API) + T8 (CLI); §7 API types → T6/T7; §8 error handling → best-effort in T5/T7; §9 tests → per-task + T9 e2e; §10 limits → omitted by design.

**Two deliberate refinements of the spec (recorded here, not in a separate doc):**
1. Message sync is REPLACE (`SyncMessages` delete-then-insert), not the spec's "INSERT OR IGNORE idempotent" — a rewritten JSONL invalidates old seq numbers, so insert-or-ignore would leave stale rows. The `UNIQUE(session_hetu,seq)` stays as a backstop.
2. `DiscoveryScheduler.Run` previously minted a fresh `uuid.NewString()` per discover; `UpsertSession`'s `ON CONFLICT ... hetu_id=excluded.hetu_id` meant the id churned every run. T5 fixes this to reuse the existing hetu_id — a required precondition for message foreign keys. This is a latent v0.1 bug the M1 work necessarily surfaces and fixes.

**Type consistency:** `store.Message{Seq,Role,Content,TS}` (T2) ↔ `agent.DiscoveredMessage{Seq,Role,Content,TS}` (T4) mapped in T5; `api.MessageDTO{Role,Content,Seq,TS}` (T6) from `store.Message`; `store.SearchHit{HetuID,Hits,Snippet}` (T3) → `api.SearchResultDTO{HetuID,Agent,Title,ProjectPath,Hits,Snippet}` (T7). `GetSession` signature change (T6) is consumed by T8. `Search` return-type change (T7) consumed by T8. Consistent.

**Open risk:** T6's server returns a fixed 20 messages; `--limit` is client-side truncation for M1 (flagged in T8). A server-side `limit` param is a small follow-up if needed — not required by the spec's "recent 20" default.
