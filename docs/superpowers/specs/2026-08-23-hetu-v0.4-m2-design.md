# Hetu v0.4 M2 — Web 前端（HTTP server + Vue3）

> 日期：2026-08-23　状态：待评审（Draft for review）
> 上游：v0.4 M1 [./2026-08-23-hetu-v0.4-m1-design.md](./2026-08-23-hetu-v0.4-m1-design.md)（数据层 + 搜索 API，已合并）；完整需求 [../../requirements.md](../../requirements.md)（§9 会话详情、§12 会话搜索）。
> 本文件是 v0.4 第二个里程碑（M2）的**实现规格**：在 hetud 内加 HTTP server + Vue 前端，复用 M1 数据层与搜索 API。

---

## 1. 目标与非目标

**目标（M2）**
- hetud 提供 **HTTP server**（绑定 localhost），输出 JSON API + 托管静态前端。
- **Vue3 + Vite + TypeScript** 前端：浏览项目 → 会话列表 → 会话详情（transcript）、全文搜索。
- 分发：**release 用 `go:embed` 内嵌 `web/dist`**；**开发时从磁盘 serve**。
- 数据层与搜索 API 完全复用 M1，不重写。

**非目标（推后）**
- Web 端操作类功能（resume/send/approve/deny/watch/实时订阅）→ 后续里程碑。
- 驱动的实时消息流接入 FTS / WebSocket 推送 → M2 后评估。
- 认证/多用户/远程访问 → 单机 localhost 可信模型，不做。
- 前端深翻页、过滤组合、高亮 UI 增强 → 后续。

## 2. 关键决策

| 项 | 决策 | 理由 |
|---|---|---|
| HTTP 接入方式 | HTTP handler 构造 `api.Request` 后调用现有 `Server.dispatch(ctx, w, req)`，`w` 为 `io.Writer` 适配器（把 newline-JSON `api.Response` 转成标准 HTTP JSON + 状态码） | **零重复**：所有业务逻辑（store/manager 调用、错误处理、DTO 映射）复用 RPC 层；CLI 的 unix-socket 路径完全不动 |
| HTTP server 归属 | 放在 `internal/daemon` 包内（`web.go`），可访问未导出的 `dispatch` | 同包最简；不需导出 API |
| 绑定地址 | 默认 `127.0.0.1:19191`，`--web-addr`/`HETU_WEB_ADDR` 覆盖；`--no-web` 关闭 | localhost-only 安全模型；端口可配 |
| 默认开启 | `hetud serve` 默认同时起 unix socket + HTTP；`--no-web` 关闭 | M2 的目的就是 Web 可用；unix socket 路径向后兼容 |
| 静态资源 | 内嵌 `web/dist`（`go:embed`）；`--web-dir <dir>` 指定磁盘目录（Vite 构建产物），dev 时覆盖内嵌 | disk serve（dev）+ release embed 双模式，M1 已定 |
| API 形态 | REST 风格 GET 端点（projects/sessions/session detail/search/discover），内部映射到现有 RPC op | 前端 fetch 直观；复用 dispatch 保证行为一致 |
| 范围 | **只读浏览 + 搜索** | 最小可用；操作类后续 |
| 前端状态 | 无状态 + 简单视图；不做 Vuex/Pinia | 最小依赖 |

## 3. 架构

```
                    ┌─────────────────────────────────────────────┐
                    │                   hetud                     │
  CLI (unix socket) │  Server.dispatch(ctx, io.Writer, api.Request) │
  ─────────────────►│       ▲                  ▲                    │
                    │       │ io.Writer        │ io.Writer           │
                    │  socket handler    HTTP handler (web.go)      │
  Browser  ────────►│  (newline JSON)   (httpWriter 适配器)          │
  (Vue SPA)         │                       │                       │
                    │              GET /api/* → dispatch            │
                    │              GET /      → 静态前端 (embed/disk)│
                    └─────────────────────────────────────────────┘
```

- 复用对象：`store.Store`、`SessionManager`、`DiscoveryScheduler`、`Server.dispatch`。
- `httpWriter`（实现 `io.Writer`）：每个 `Write` 收到 `api.Encode` 写出的 newline-JSON `api.Response`；`OK=true` → 200 + 原样写 `Body`（已是 JSON）；`OK=false` → 4xx/5xx + `Err` 文本。

## 4. HTTP API（web.go）

| 方法 + 路径 | 参数 | 内部 RPC op | 响应体 |
|---|---|---|---|
| `GET /api/projects` | — | `list_projects` | `[]ProjectDTO` |
| `GET /api/sessions` | `project_path` `status` `agent` | `list_sessions` | `[]SessionDTO` |
| `GET /api/sessions/{id}` | 路径 `{id}`（支持前缀） | `get_session` | `{session: SessionDTO, pending: [...], messages: [MessageDTO]}` |
| `GET /api/search` | `q` | `search` | `[]SearchResultDTO` |
| `POST /api/discover` | — | `discover` | `{ok: true}` |

- 错误：`OK=false` 的 op → 4xx（400）或 5xx（500，视错误类型）；body 为 `{"error": "<msg>"}`。
- `GET /api/sessions/{id}` 的 `{id}` 走 `ResolveSession`（支持短前缀），未找到 → 404。
- 不暴露流式 op（`watch`/`subscribe`）与写操作（`approve`/`send`/`resume`/`create`）——M2 只读。

### 静态资源
- `GET /` 与无 API 前缀的路径 → 前端 index.html + 资源。
- 内嵌模式：`//go:embed web/dist`（`web/dist` 为空时 embed 失败——构建前先 `npm run build`，或用空 `index.html` 占位）。
- 磁盘模式：`--web-dir <dir>` 时用 `http.FileServer(http.Dir(dir))` 覆盖。

## 5. 配置与启动（cmd/hetud）

`serve` 子命令新增 flags：
- `--web-addr`（默认 `127.0.0.1:19191`；空串 = 关闭 HTTP）
- `--web-dir`（默认空 = 用内嵌 `web/dist`）
- 环境变量 `HETU_WEB_ADDR` 作为 flag 的 fallback。

启动流程（serveRun 内，`srv.Serve` 之前/之后）：
1. 构造 `web.NewServer(st, srv, addr, webDir)`。
2. goroutine `webSrv.ListenAndServe(ctx)`；ctx 取消时 `Shutdown`。
3. 与 unix socket server 一起在 `errCh`/`select` 中管理，graceful shutdown 两个都关。

## 6. 前端（web/，Vue3 + Vite + TS）

目录结构：
```
web/
  package.json          # vue, vue-router, vite, typescript, @vitejs/plugin-vue
  vite.config.ts        # dev 时 proxy /api → http://127.0.0.1:19191
  tsconfig.json
  index.html
  src/
    main.ts             # createApp + router
    router.ts           # /projects, /sessions, /sessions/:id, /search
    api.ts              # fetch 封装：projects()/sessions()/session(id)/search(q)/discover()
    types.ts            # 与 api.SearchResultDTO 等对齐的 TS 接口
    views/
      ProjectsView.vue      # 项目卡片/列表（名称、路径、会话数、attention）
      SessionsView.vue      # 会话列表（过滤 project/agent/status），可点进详情
      SessionView.vue       # metadata + transcript（chronological）+ 搜索内跳转
      SearchView.vue        # 输入框 + 结果（title、hits、snippet），点击进会话
```
- 风格：极简、无 UI 框架依赖（手写 CSS），聚焦信息密度（会话/搜索是核心）。
- 数据：`api.ts` 直接 fetch `/api/*`；无全局状态库。
- 构建：`npm run build` → `web/dist`（`vite build`），供 `go:embed`。

### Makefile 集成
- `make web`：`cd web && npm install && npm run build`。
- `make build`：先 `web` 再 `go build`（保证 embed 到最新 dist）。
- `make dist`：沿用现有跨平台循环。

## 7. 安全与错误处理

- 仅绑定 `127.0.0.1`（默认），不对外暴露；无认证（单机可信模型，文档注明）。
- API 错误：复用 dispatch 的 `replyErr` 语义；前端对非 2xx 显示错误 toast/内联。
- 搜索空 `q`：返回空结果（不 500）。
- 静态资源 404：返回 index.html（SPA 路由回退）——`/api/*` 前缀除外。

## 8. 测试策略

- **web.go（daemon 包）**：`httptest` 起 server → `GET /api/projects`、`/api/sessions`、`/api/sessions/{id}`（含消息）、`/api/search` 断言 JSON；未知路径 404；`GET /` 返回 index。复用 client_test 的 store seed 模式。
- **main.go wiring**：`--web-addr` 解析、`HETU_WEB_ADDR` fallback、`--no-web`（config 单测）。
- **前端**：构建通过（`npm run build` 无 TS 错误）；API 层与后端类型对齐（人工核对 + 后端 e2e）。
- **e2e（gated，真实环境）**：起 hetud（含 web）→ `curl /api/projects` 有数据 → `curl /api/search?q=<词>` 命中 → `curl /api/sessions/<id>` 有 messages → 前端构建产物可加载（浏览器打开 / 返回 index.html + api 通）。

## 9. 限制与未来

- Web 端只读：resume/send/approve/实时推送为后续里程碑（可复用 RPC op + WebSocket）。
- 前端无深翻页/复杂过滤/高亮。
- 无认证与远程访问。
- M2 后：driven session 实时消息入 FTS、WebSocket 推送、多引擎内容展示。
