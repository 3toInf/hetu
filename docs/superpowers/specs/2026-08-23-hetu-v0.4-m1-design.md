# Hetu v0.4 M1 — 会话内容 + 全文搜索（数据层与命令行）

> 日期：2026-08-23　状态：待评审（Draft for review）
> 上游：完整需求 [../../requirements.md](../../requirements.md)（§9 会话详情、§12 会话搜索）；v0.3 设计 [./2026-08-23-hetu-v0.3-design.md](./2026-08-23-hetu-v0.3-design.md)。
> 本文件是 v0.4 第一个里程碑（M1）的**实现规格**：把 Claude 会话的 transcript 内容入库、支持全文搜索与详情展示。M2（Web 端）依赖本数据层，另立 spec。

---

## 1. 目标与非目标

**目标（M1）**
- **transcript 内容入库**：discovery 时把每个会话的 user/assistant 消息文本写入 store，并建 FTS5 全文索引。
- **会话详情展示内容**：`hetu session <id>` 在 metadata 之外显示对话记录。
- **全文搜索**：`hetu search <query>` 从"标题 LIKE"升级为搜对话内容（FTS5）+ 标题兜底。

**非目标（推后）**
- Web 端（HTTP server + Vue 前端）→ M2。
- 搜索 tool 调用 / tool 结果、按 role/时间/项目过滤搜索 → 后续。
- 多 CLI 会话内容（Codex/OpenCode）→ v0.5。
- 搜索高亮 UI / 分页深翻（M1 只做单页结果 + snippet）。

---

## 2. 关键决策

| 项 | 决策 | 理由 |
|---|---|---|
| 存储结构 | **双表**：普通表 `session_messages`（展示/排序）+ FTS5 表 `session_messages_fts`（索引） | FTS5 虚拟表为 token 索引优化，不适合结构化排序与完整展示；双表职责清晰 |
| 索引内容 | **只索引 text**（user/assistant 消息的 `type:"text"` 块），tool_use/tool_result 不索引 | tool 噪音大；"搜用了某工具"是次要需求，先不做 |
| 入库时机 | discovery 时，随 metadata 一起 | 复用现有 discovery 流程，单一入口 |
| 增量策略 | **按 JSONL 文件 mtime**：`sessions.content_synced_at` 记录上次同步，文件未变则跳过内容重扫（metadata 仍幂等刷新） | 避免每次 discover 全量重插数百会话内容 |
| 消息幂等 | `UNIQUE(session_hetu, seq)` + `INSERT OR IGNORE` | 重复发现不产生重复行 |
| seq 定义 | JSONL 行序（0 起） | 稳定、与文件结构一致 |
| 搜索 query | 用户输入按 **phrase 查询**处理（双引号包裹），不进 FTS5 操作符语法 | 防 "foo OR bar" 被解析为逻辑或 |
| 搜索排序 | 按 session 命中数降序，返回每 session 一个 snippet | 命中多的会话排前，片段展示命中上下文 |

## 3. 数据模型（migration `003_messages.sql`）

```sql
-- 结构化消息：展示、排序
CREATE TABLE session_messages (
  session_hetu TEXT NOT NULL REFERENCES sessions(hetu_id),
  seq          INTEGER NOT NULL,
  role         TEXT NOT NULL,             -- 'user' | 'assistant'
  content      TEXT NOT NULL,
  ts           INTEGER,
  UNIQUE(session_hetu, seq)
);
CREATE INDEX idx_messages_session ON session_messages(session_hetu, seq);

-- 全文索引
CREATE VIRTUAL TABLE session_messages_fts USING fts5(
  session_hetu UNINDEXED,
  role         UNINDEXED,
  content
);

-- 增量同步标记
ALTER TABLE sessions ADD COLUMN content_synced_at INTEGER;
```

`session_messages_fts` 不建 `content=` 外部内容表（external content），而是独立表 + 手动同步——简单、无触发器维护负担；写入时同事务双写。

## 4. 内容提取（internal/claude/discovery.go）

`parseTranscript` 扩展：除现有 metadata 外，逐行提取消息，返回 `[]Message{Seq, Role, Content, TS}`。

- 仅处理 `Type ∈ {user, assistant}` 的行。
- `role` = 行 `Type`（"user"/"assistant"）。
- `content` = 遍历 `message.content`（array），拼接所有 `type:"text"` 的 `text` 字段（多 text 块用 `\n` 连接）；无 text 块的行跳过（不产生消息行）。
- `seq` = 该行在 JSONL 中的 0 起索引。
- `ts` = `parseTimestamp(l.Timestamp).Unix()`（沿用现有 parse）。

> 提取失败/坏 JSON 行照旧跳过，不影响整体发现。

`agent.DiscoveredSession` 增加 `Messages []DiscoveredMessage` 字段（`internal/agent/agent.go`），`DiscoveredMessage{Role string; Content string; Seq int; TS int64}`。

---

## 5. 入库（store + daemon DiscoveryScheduler）

- `store.UpsertMessages(ctx, hetuID string, msgs []store.Message) error`：单事务内，逐条 `INSERT OR IGNORE INTO session_messages` + `INSERT OR IGNORE INTO session_messages_fts(session_hetu, role, content)`；空消息列表跳过。
- `store.SetContentSynced(ctx, hetuID string, unix int64) error`：更新 `sessions.content_synced_at`。
- `store.ContentSyncedAt(ctx, hetuID) (int64, bool, error)`：读取上次同步时间（供 discovery 判断）。

**增量判断（discovery 侧）**：`Discover` 拿到文件 `mtime` 后，与 store 里该 `external_id` 对应 session 的 `content_synced_at` 比对：`mtime ≤ synced` 且内容已同步过 → 只刷新 metadata，跳过消息提取；否则提取消息 + `UpsertMessages` + `SetContentSynced`。

> DiscoveryScheduler 目前只管 metadata upsert；本次把消息 upsert 并入同一流程（`internal/daemon/discovery.go`），store 的 `UpsertSession` 与消息写入需在调度器内协调（session 行先 upsert 得到 hetu_id，再写消息）。

## 6. 命令形态（internal/cli）

### 6.1 `hetu session <id>`

在现有 `printSessionDetails` 之后追加 transcript：
```
ID: ...
Agent: ...
Status: ...
...
── Messages (recent 20 of 87) ──
user: 这个 websocket 断连的问题怎么排查？
assistant: 先看客户端和服务端的握手日志……
```
- 新增 flag `--limit`（默认 20，`--limit 0` = 全部）。
- 数据来源：新增 `store.RecentMessages(ctx, hetuID, limit)`（`ORDER BY seq DESC LIMIT ?`，展示时反转为正序）。
- server：`get_session` op 扩展返回 `messages` 数组（`api.MessageDTO{Role, Content, Seq, TS}`）；CLI `session` 命令渲染。

### 6.2 `hetu search <query>`

从 title LIKE 升级为 FTS5 全文 + 标题兜底：
- server `search` op：先 FTS5 搜 `session_messages_fts`（phrase query），按 `session_hetu` 聚合命中数 + 取每 session 一个 snippet；再对命中不足的情况用 title LIKE 兜底（`hetu_id NOT IN 已命中`）。
- 返回 `[]api.SearchResultDTO{HetuID, Agent, Title, ProjectPath, Hits, Snippet}`。
- CLI 渲染：
```
[claude] websocket 断连排查              (3 hits)
  … 先看客户端和服务端的[握手日志]……
```

## 7. 服务端 API（internal/api + internal/daemon/server.go）

- `MessageDTO{Role string; Content string; Seq int; TS int64}`。
- `get_session` op：响应体加 `messages []MessageDTO`（默认最近 20，`--limit` 透传；0 = 全部）。
- `search` op：请求体不变（`SearchReq{Q}`），响应从 `[]SessionDTO` 改为 `[]SearchResultDTO`（含 snippet/hits）。兼容旧 CLI：CLI 同步更新。

---

## 8. 错误处理

- 消息写入失败：discovery 单 session 失败不影响其他 session（记录日志，继续）。
- FTS5 表损坏/缺失：迁移保证存在；运行期错误按 best-effort 降级（search 空结果 + 日志）。
- 坏 JSON 行 / 无法提取 text 的行：跳过，不中断。
- 搜索 query 为空：`search` 要求 `ExactArgs(1)`，空串由 cobra 拒绝。

## 9. 测试策略

- **store**：`UpsertMessages` 幂等（重复 upsert 行数不变）、FTS5 短语搜索命中、`RecentMessages` 排序/limit、`SetContentSynced`/`ContentSyncedAt` 往返。
- **claude**：`parseTranscript` 用 JSONL fixture 断言提取的 Message 序列（含多 text 块拼接、tool 块跳过、坏行跳过）。
- **daemon**：discovery 增量——同 mtime 第二次 discover 不重写消息（消息数不变）、mtime 更新则刷新。
- **cli**：`session` 详情含 transcript 渲染、`search` 含 snippet/hits 渲染（golden/往返，复用 in-process server harness）。
- **e2e（真 claude，gated）**：discover 真实 `~/.claude` → `hetu search <某个历史会话里出现过的词>` 命中；`hetu session <id>` 显示对话。

---

## 10. 限制与未来

- M1 只索引 text，不搜 tool 调用/结果。
- 搜索单页结果，无深翻/过滤。
- 内容随 discovery 更新，非实时（driven session 的实时事件流另属 session_events，不并入 FTS）。
- M2：HTTP + Web 前端复用本数据层与搜索 API；M2 后评估 driven session 实时消息入 FTS。
