# Hetu v0.3 — 设计规格（Design Spec）

> 日期：2026-08-23　状态：待评审（Draft for review）
> 上游：完整需求 [../../requirements.md](../../requirements.md)；v0.2 设计 [./2026-08-14-hetu-v0.2-design.md](./2026-08-14-hetu-v0.2-design.md)（已合并，PR #8）。
> 本文件是 v0.3 的**实现规格**：可配置审批策略（allowlist）+ watch 退订生命周期 + 日志层。

---

## 1. 目标与非目标

**目标（v0.3）**
- **可配置审批策略**：用户可写"工具+参数模式"的自动放行/拒绝规则，替代 v0.2 硬编码只读集；规则对 agent 无感（写在规范工具类上），为 v0.5 多引擎铺路。
- **watch 退订生命周期**：订阅者断开后清理其 channel，消除慢性泄漏。
- **日志层**：标准库 slog,把 v0.2 静默吞掉的 best-effort 错误与审批裁决亮出来。

**非目标（推后）**
- defer/resume 长等待（破 9 分钟审批上限）→ 后续版本。
- 项目级规则（`.hetu/rules.json` 叠加/优先级）→ 有真实需求再做。
- Codex / OpenCode adapter → v0.5（本版只留好接缝：提取器注册制）。
- 规则按 session 临时放行（"本次允许"）、TTL、统计面板 → 后续。

---

## 2. 关键决策

| 项 | 决策 | 理由 |
|---|---|---|
| 规则粒度 | **工具类 + 参数模式**（`Shell(git status:*)`、`Edit(/path/**)`、`Fetch(domain:x.com)`） | 只按工具名放行 ≈ `allow Bash` 放行一切命令，没人敢配；参数模式才能真正降噪音。语法对齐 Claude Code 权限规则子集，零学习成本 |
| 引擎归属 | **自建 `internal/policy`**,决策仍在 hetud 的 hook 回调内 | 单一裁决点：可测试、可记录、无 `--allowedTools` 与 hook 优先级的未文档化交互；`--allowedTools` 是 claude 私有 flag,多引擎不通用 |
| 规则作用层 | **规范工具类（canonical kinds）**,非原生工具名 | 一份规则三引擎通用（v0.5 Codex/OpenCode 各加一个提取器即可）；claude 原生名在适配层作别名 |
| 规则存放 | 全局 `~/.hetu/rules.json`（`HETU_RULES` 可覆盖）+ `hetu allow add/rm/list` CLI | 单一事实源、可手改可版苹；项目级规则推后 |
| 默认规则 | 首次运行写入 `{"allow":["Read"]}` | v0.2 硬编码只读集（Read/Glob/Grep/LS）降级为文件里的默认内容,用户可 `!Read` 收紧 |
| 优先级 | **deny 规则 > allow 规则 > 默认问人** | 安全默认:显式拒绝永远赢;无命中必问人 |
| 热加载 | 每次裁决前比对 mtime,变化即重载 | 改规则不用重启 daemon;本地文件 stat 开销可忽略 |
| 退订 | `Subscribe` 返回 `(sub, cancel)`,流退出路径统一 `defer cancel()` | 由构造保证幂等清理,杜绝漏调;O(n) 按身份扫描删除(订阅者量级小) |
| 日志 | 标准库 slog;`~/.hetu/hetud.log` + 前台 stderr;`HETU_LOG_LEVEL` 调级;5MB 单档轮转 | 零新依赖;CLI 保持安静;轮转自写 ~30 行 |

## 3. 规则引擎（internal/policy）

### 3.1 规范工具类与提取器

```
Shell   命令执行        Edit    文件写入/修改     Read   文件读取
Fetch   网络获取        Search  搜索             Other  未归类（默认问人）
```

**per-agent 提取器（注册制，v0.3 仅 claude）**：`Extractor(agent string) → (kind Kind, subject string, ok bool)`,输入 `(toolName, toolInputJSON)`:

| claude 工具 | kind | subject 取自 |
|---|---|---|
| Bash | Shell | `tool_input.command` |
| Write / Edit | Edit | `file_path` |
| NotebookEdit | Edit | `notebook_path` |
| Read | Read | `file_path` |
| Glob / Grep / LS | Read | `path` |
| WebFetch | Fetch | `url` → 取 host |
| WebSearch | Search | — |
| 其余/未知 | Other | — |

提取失败（入参缺字段/坏 JSON）→ `(Other, "", false)` → 问人（安全默认）。v0.5 的 codex/opencode 各实现一个提取器注册进来,规则零改动。

### 3.2 规则语法与匹配语义

```
[!]Kind[(specifier)]

Shell(git status:*)      # 命令前缀（"git status" 开头）
Shell(npm test)          # 精确命令
Edit(/home/x/repo/**)    # 路径 glob：* 单段、** 跨段,匹配绝对路径
Fetch(domain:github.com) # 域名后缀（含子域）
Read                     # 裸类 = 整类
!Shell(git push:*)       # 拒绝
```

- Shell specifier:无 `:*` 后缀 = 精确匹配;有 = 前缀匹配（比对前 trim 空白）
- Edit/Read specifier:glob,`**` 跨目录段、`*` 段内任意,匹配**绝对路径**;相对路径写法的规则不参与命中（v0.3 规则一律绝对路径,不做 cwd 猜测）
- Fetch specifier:`domain:` 前缀,host 等值或以 `.domain` 结尾
- Search/Other:只支持裸类
- 解析规则非法（未知 Kind、括号不闭合、空 specifier 等）→ add 时报错,文件中存在则**该条忽略并记日志**（一条坏规则不瘫痪整个策略）

### 3.3 裁决与接入点

```go
func (p *Policy) Decide(kind Kind, subject string) Decision  // Allow / Deny / Ask
```

deny 命中 → Deny;否则 allow 命中 → Allow;否则 Ask。`SessionManager.RequestPermission` 内：替换 `readOnlyTools` 硬编码,改调 提取器 + `policy.Decide`;Allow/Deny 直接返回（**不注册 pending、不广播**）,Ask 走现有 ApprovalBroker。每次裁决记 slog（见 §5）。

### 3.4 文件格式与 IO

`~/.hetu/rules.json`：
```json
{"allow": ["Read", "Shell(git status:*)"], "deny": ["Shell(git push:*)"]}
```

- `policy.Load(path)`:文件不存在 → 返回默认策略（含默认写盘动作由 daemon 首启执行）;坏 JSON → 报错（daemon 降级为"全问人"并日志告警,不 crash）
- `policy.Save(path, rules)`;`policy.Parse(rule string) (Kind, subject, effect, error)` 供 CLI 校验
- 热加载:daemon 缓存 `(mtime, *Policy)`,裁决前 stat 比对

## 4. CLI — `hetu allow`

```
hetu allow list                          # allow / deny 两组列出（含解析告警）
hetu allow add "Shell(git status:*)"     # 追加 allow;--deny 追加 deny
hetu allow rm "Shell(git status:*)"      # 按规则文本删;--deny 组
```

- add/rm 走 `policy.Parse` 校验,非法规则报错不入文件;保存为 原子写（临时文件 + rename）
- 规则路径同 daemon（`config.RulesPath()`,honors `HETU_RULES`）
- 无需通知 daemon 热加载——mtime 机制自动生效

---

## 5. 日志层（internal/logx + 接入）

- `logx.Setup(opts) *slog.Logger`:`HETU_LOG_LEVEL`（默认 info）;输出 `~/.hetu/hetud.log`,`--stderr`(前台 serve)叠加 stderr;轮转:超 5MB rename 为 `.log.1`（仅留一档）
- 接入点（v0.2 的静默 `_ =` 全部替换为日志 best-effort）:
  - daemon 启停、会话 Ensure / pump 退出 / 最终状态
  - `RequestPermission` 每次裁决:`hetu_id / tool / kind / rule / decision` 结构化字段;转人工的在其 resolved 时补记
  - hook RPC 错误、notify 失败、store best-effort 错误、规则文件坏行忽略
- 注入方式:构造参数传入（测试用内存 handler 断言）,包级默认 `slog.Default()` 兜底

---

## 6. watch 退订

- `SessionManager.Subscribe(hetuID) (<-chan agent.Event, cancel func(), error)`:cancel 闭包幂等（sync.Once）,在 `l.mu` 下按 channel 身份删除并 close
- 服务端 `watch`/`subscribe` handler:拿到 cancel 即 `defer cancel()`,覆盖所有退出路径（写失败 break、断连、shutdown）
- 兼容:daemon 内部测试现有调用点同步改造

---

## 7. 测试策略

- **policy 单测**:各匹配器表驱动（前缀/精确/glob 含 `**`/域名后缀含子域）;优先级 deny>allow>ask;Parse 合法/非法全集;Load/Save 往返;坏 JSON 降级
- **提取器**:claude 全工具映射表驱动;缺字段/坏 JSON → Other
- **daemon 集成**（fake 会话）:命中 allow → 直接 allow 且**无 pending 注册**;命中 deny → deny;无命中 → ApprovalBroker(既有断言);热加载:改文件后下一次裁决用新规则
- **CLI**:`allow add/rm/list` 往返、非法规则被拒、--deny 组
- **退订**:订阅 → cancel/断连 → subscribers 空、channel 已关
- **logx**:级别过滤、轮转触发
- **e2e(真 claude,gated)**:规则 `Shell(touch:*)` → touch 不弹审批直接执行、日志含 `decision=allow`;无规则命令仍弹审批、approve 后执行

---

## 8. v0.3 限制与未来

- 规则仅全局;无"本次允许"/TTL;无按会话临时放行
- Search 类无参数匹配;Other 恒问人
- 审批等待上限仍 ~535s（defer/resume 属后续版本）
- v0.5:Codex/OpenCode 提取器注册即可共享规则;项目级规则、审批统计面板后续评估
